### A. Current known problems (early alpha)
1. **Gameplay runs on 1.21.11 and 26.1–26.3 only; engine-level subsystems are still unbuilt.** The server now has a survival game layer (`crates/aether-server/src/game`: mobs, items, combat, hunger, crafting, chests, furnaces — see item 10), but it is a server-side layer, not the ECS/Flow-Field design of the roadmap; redstone and the full staged physics pipeline are not implemented.
2. **SIMD parity only partially validated.** `Scalar / SSE4.2 / AVX2` paths are implemented and unit-tested; `AVX-512` is *detected* but routed to the AVX2 path — there is no native AVX-512 backend yet.
3. **Determinism unproven.** Parallel subsystems must merge at Safe Points; the merge points are specified but not validated, and the work-stealing scheduler that would exercise them does not exist yet.
4. **Experimental 1.8.9 server is unverified against a live client.** `aether-server` speaks protocol 47 in offline mode with no compression/encryption, and its framing is checked only against a raw socket client. A real Minecraft 1.8.9 client may still reject some packets (chunk-data format is the most likely gap). It binds to loopback by default and must not be exposed publicly.
5. ~~**Players are visible but not tab-listed.**~~ **Fixed:** the Player List Item packet (0x38, protocol 47) now goes out on join and leave — action 0 adds an entry with the player's **binary** UUID (16 raw bytes, the same form Spawn Player uses; only Login Success is the hyphenated string), name, an empty GameProfile property list (offline mode has no skin signature to send) and a synthetic game mode/ping; action 4 removes it. Each add is emitted *before* the corresponding Spawn Player, because a 1.8 client drops a spawn for a UUID it has no tab entry for. With no properties a client shows the default Steve/Alex skin, which is the correct result for offline mode. The exact byte layout is pinned by a unit test.

6. **Block states work, except where they depend on a neighbour.** `BlockStateId` is now the vanilla flattened block-state id (29,671 states over 1,166 blocks — see [DESIGN_NOTES §9](DESIGN_NOTES.md)), and placement chooses a state from the player's yaw and pitch, the clicked face and the cursor. Re-measured against a live 1.21.11 client (`tools/probe/states3.js`):

   | placed | before | now |
   |---|---|---|
   | `oak_stairs`, looking N/E/S/W | `facing=north` in all four | follows the look direction |
   | `oak_slab` on a top face | `type=bottom` | `type=bottom` |
   | `oak_slab` on a **bottom** face | `type=bottom` | `type=top` |
   | `oak_door` | `half=lower` only, air above | two blocks, `lower` + `upper`, facing agrees |
   | placed into water | `waterlogged=false` | `waterlogged=true` |
   | two adjacent `oak_fence` | no connections | connect, in either build order |

   **Neighbour-dependent shapes settle both ways now.** A block-update pass (`placement::neighbour_updates`) re-runs when a neighbour changes, so a fence built *away* from an existing one connects instead of keeping the unconnected shape it was born with. It covers fences, walls, panes/bars and stair corners — the families whose shape is a pure function of the six touching cells.

   what is left is the class of property that needs a wider propagation than a single reshape: redstone wire shape; a door's hinge side; grass turning `snowy`. A fence placed today is a correct, connected fence.

   **Interaction now beats placement.** Clicking a door, trapdoor or fence gate toggles it instead of building against it — the reported "door opens and instantly shuts with a block in front of it" was the server placing a block where the client had predicted an opening, and the ack then reverting the prediction. Both halves of a door toggle together. Sneaking still builds against it, or a door could never be placed beside another. Detected from the block's own data — anything declaring an `open` property — so there is no list to maintain.

   **Stairs take their corner shape**, transcribed from `StairBlock`'s bytecode in the 1.21.11 server rather than from memory: the four corner cases differ only in which of `left` and `right` they name. Computed at placement, and re-computed by the neighbour-update pass when a neighbour changes — both places vanilla computes it.

   **Open question, measured but not explained:** a headless client's *view* of a toggled door trails the server by a click or two, while the server's own state is right every time and nothing is placed in front. It may be the client's prediction handling rather than ours — mineflayer's differs from the game's — so this wants checking with a real client before it is chased.

   Three smaller gaps inside the part that does work:
   - **Attachment-based facing is not distinguished from look-based facing.** A ladder or a wall torch takes its direction from the surface it is on; nothing in the block's own data says so, and they get the look-based answer.
   - **Anvils are 90 degrees out.** `AnvilBlock` uses `getClockWise()`, a third rule that is not implemented.
   - **Properties do not vary within a block, except collision.** An unlit redstone lamp still emits nothing, a double slab is not a full opaque cube, an open trapdoor still occludes light as its closed form. `minecraft-data` publishes light and occlusion per *block*, not per state, so `STATE_PROPS` stays uniform within a block; closing the light half means asking the game itself, which is the technique the worldgen work uses. **Collision is now the exception**: the boxes come per state from `blockCollisionShapes` (see the next item), so an open door or gate no longer collides, a top slab sits in the upper half and a fence is 1.5 tall.

7. ~~**The 1.17 / 1.17.1 chunk encoding is rejected by a real client.**~~ **Fixed:** the section encoder wrote 1.18's *single-valued* palette (`bits per entry = 0`) whenever a section held one repeated block, which the old code also used for every empty section. 1.17 predates that form (it first appears in `PaletteType1_18`), so a client read the palette value as a length, consumed the wrong number of bytes and ran off the buffer — surfacing as `Attempted to read beyond the bounds of the managed data` while reading the next section's block count. Sections are now encoded exactly as 1.17 requires: a big-endian non-air count followed by a **4-bit indirect** palette, and an all-air section is **omitted from the section bitmask** entirely, which is also what the vanilla server does — it never sends an empty section. Byte-level tests pin one section and an empty column; both 1.17 and 1.17.1 are covered.

8. **Vanilla worldgen: decoration is vanilla-like, not exact; some features and most structures are missing (only the igloo is placed).** Terrain shape, biomes, surface rules (now including `temperature`, `steep`, `hole` and badlands banding) and carvers are matched stage by stage against the game's own generator. The decoration step runs the pack's placed features with the game's seeds and order, and lands 99.7% of all blocks and 96.7% of top blocks against a vanilla server world — but it is not position-exact: vanilla's result depends on which neighbouring chunks were decorated first, and trees, ores and plants overlapping a chunk border settle differently. Leaf `distance` values differ in a few percent of leaves. Not generated at all: structures (villages, mineshafts, strongholds…), sculk, root systems. Desert wells, dungeons (`monster_room`), geodes, fossils, pointed dripstone and multiface spreading (glow lichen) are ported. `minecraft:cinnabar` and `minecraft:sulfur` are not in this engine's block registry, so those surface leaves fall through rather than placing a substitute.

   **Biomes are sent on 1.21.11:** the codec registers all 65 biomes (temperature and precipitation from `minecraft-data`, rainfall and water colours by family, vanilla's sky-colour formula) and writes each section's 64 entries as a paletted container; the other codecs and the noise generator still show plains. The block containers also widen past four bits — a decorated section with more than sixteen states used to corrupt the column.

   **Throughput is no longer the problem.** It was: the generator once managed 35 columns in 120 s against a live client, about 10 s a column. Two bugs in the density graph's node cache did it — the `cache_once` / `cache_2d` / `flat_cache` markers were no-ops that memoized nothing, and the cell-corner cache packed `x0`/`y0`/`z0` into overlapping bit ranges, so with `min_y = -64` it collided on nearly every lookup. A third fix sized the corner cache to the real working set. Measured against a real 1.21.11 client at view radius 8: **spawn at 1.87 s, all 289 columns in ~21 s** cold, and within the first five seconds once the column cache is warm.

9. **No headless-client regression suite yet.** `tools/probe` connects a real 1.21.11 client (mineflayer) and reports what the server actually sends; it found two live defects in one run — a seven-entry item→block table that placed every other block as **stone**, and a missing `set_health` that stalled every bot client before spawn. It is a set of scripts, not a test suite, and nothing runs it automatically. For 26.x, `tools/wire` goes further: a client compiled against the release's own server jar decodes every packet with the game's codecs and builds the registries as the client does. On its first runs it found two defects mineflayer cannot see: 26.3's byte-array `BitSet` (every chunk's light masks misread) and cave/void air counted as blocks in each section's non-air count. It needs the release's jar and Java 25, so CI does not run it either.

10. **What the survival layer does not do yet** (1.21.11 and 26.1–26.3; every older codec ignores the gameplay events and keeps its older, client-trusting subset — no mobs, no server-side windows):
    - **Mob AI is straight-line.** Mobs walk towards their goal, jump one-block steps and refuse unclimbable drops; there is no pathfinding around obstacles, no door opening, no climbing for spiders. Eight kinds exist: cow, pig, sheep, chicken, zombie, skeleton, creeper, spider. No breeding, taming, villagers or the Nether/End mobs.
    - **No redstone or fire spread.** Falling sand/gravel/concrete powder, crop growth (wheat, carrots, potatoes, beetroot, sugar cane, cactus) and leaf decay **do work** now (`game/blockticks.rs` and its submodules, driven by the scheduled queue and a vanilla-rate random-tick pass — three blocks per 16³ section per tick). The scheduler is durable now: its pending ticks are written per chunk (`game/tickstore.rs`) and reloaded as each chunk comes in, so a restart no longer drops a fall or a growth. Two deviations there: **light is treated as full-bright**, so crops grow in the dark and under a roof where vanilla's `>= 9` check would refuse; and the `DIRT`/`SAND`/`LOGS` block tags the support and distance rules read are name lists, not the real tags. Crops still cannot be bone-mealed. Water and lava **do flow** now (`game/fluids.rs`: scheduled updates with vanilla delays, levels, falls, slope-seeking, infinite water, lava + water → obsidian/cobblestone/stone), but flowing water does not push mobs or items, waterlogged blocks do not flow, and generated water only starts moving when something next to it changes.
    - **No enchanting, brewing, anvils, smithing or villager trading; beds only set the spawn point and skip the night.** Status effects **do** now work (`game/effects.rs`): the Update / Remove Mob Effect packets are sent on 1.21.11 and 26.1–26.3; golden apples, enchanted golden apples, poisonous potatoes, spider eyes, pufferfish, rotten flesh and suspicious stew apply them; and regeneration, poison (never below one heart), wither, hunger, absorption, resistance, fire resistance and speed/slowness (movement-speed attribute) are acted on. Effects tick, expire, cure with milk, and are saved with the player. Potions, beacons and conduits do not exist yet, and every other effect is carried and displayed with no server-side rule.
    - **XP orbs** are entities now (`minecraft:experience_orb`): ores, mobs killed by a player and smelting drop them on the ground; they drift to a nearby player, merge up to an orb's cap, and credit whoever picks them up. Fortune/Silk Touch do not yet change the amount (enchantments are not modelled).
    - Chests **do double**: two adjacent chests merge into one 54-slot window (`type=left`/`right`), breaking one half splits the other back to single. Hoppers (5 slots), droppers and dispensers (9 slots) **now have inventories** — the same container model as chests and furnaces (windows, persistence, provenance) — and hoppers **move items**: on the block-tick scheduler, one item every eight ticks, pulling from the container above and pushing into the container they face. What is still missing: the `enabled` redstone property is ignored (a hopper is always on), a hopper does not pick up item entities or minecart entities, and a dropper/dispenser does not fire on a redstone pulse — beyond holding their items they do nothing.
    - ~~**Block collision is per cube**~~ **Fixed:** collision boxes come per block **state**, generated from `minecraft-data`'s `blockCollisionShapes` (`registry::shapes`, generator `tools/gen/collisions.js`). Slabs collide as half cells, stairs as their step shape, fences as their 1.5-tall rails, and an open door or fence gate as nothing at all; grounded entities walk (step) up a slab but not a full block. `aether-physics` resolves an AABB against the box list and a state-aware `BlockView` supplies it.
    - **Anti-cheat is minimal**: mining time is checked at half the expected duration, reach at 6 blocks; movement is trusted.
    - **Light is not consulted for spawning**: monsters spawn at night under open sky, or at any time under cover.

11. **The journal keeps every event forever.** Loading a column no longer replays its whole history (per-column checkpoints), but the history itself still grows without bound on disk; grouped revisions and packed cold segments are the plan (ROADMAP, Phase 1 "History at scale"). Fluid flow is written without a journal entry, so in a sub-chunk rebuilt after a generator change, flowing water resets to what the generator made until something disturbs it.

12. **Item provenance has known blind spots.** A stack that merges into one already in a slot ends there (its uid is destroyed and the other's count grows), so that hop has no *derived from* edge; events are per click, not per operation, until revisions group them; the economy still journals its own moves with uids of their own beside the real ones; items in inventories from before this change were never minted, so their first event reads as an anomaly in `/audit`; fights and trades between players are not recorded yet.

13. ~~**1.20.2 through 1.20.4 cannot connect.**~~ **Fixed:** protocols 764–765 are served by their own codecs (`protocol/v764` 1.20.2, `protocol/v765` 1.20.3/1.20.4), built on the 1.20.1 (763) NBT blob. Like 1.20.1 they send the whole registry set as one blob — but with an **anonymous root**, and in the **configuration phase** 1.20.2 introduced rather than inside Play Login. Columns are wrapped in 1.20.2's **chunk-batch** flow-control packets, and 1.20.3's differences are pinned in its own module (System Chat as an NBT component, the UUID on the resource-pack packet, game event 13 for "wait for chunks", and the moved `minecraft:player` entity-type id). 1.20.2 also reordered the Unload Chunk packet to Z-before-X, which its module follows. As with the 1.20.1 codec, the registry blob stays minimal (dimension type, biome, chat type). Verified by encode/decode tests only; no live client of these versions was available.


14. **Older codecs translate and substitute blocks; 1.8.9 now resolves every engine block.** Queue J's compat layer (`crates/aether-server/src/protocol/compat`, generated by `tools/gen/compat/gen.js` from `blocks.json` + PrismarineJS `minecraft-data`) maps every engine block state into each older release's own numbering by name and properties, and substitutes the closest block a version lacks — `pale_oak_*` → `oak_*`, `cherry_*` → `birch_*`, `copper_bulb` → `copper_block`, `crafter` → `dispenser`, `trial_spawner` → `spawner`, `heavy_core` → `iron_block`, `mud_bricks` → `bricks`, deepslate/copper/tuff families and so on. The rules chain, so `bush → short_grass → grass` lands on the oldest name that exists. **Every release from 1.17 through 1.21.10 resolves every engine block** (zero stone fallbacks). 1.8.9 (protocol 47) is pre-flattening: a cell is `(id << 4) | meta`, so it has only 198 blocks and a variant is told apart by its metadata. The rules carry that metadata (`metaMaps` for colour/wood/coral and a literal elsewhere), so a wool colour, a wood type, a flower species, a coral colour or a slab variant lands on the right one instead of its block's default. **1.8.9 now resolves every engine block too — `gen::v1_8::STONE_FALLBACKS` is empty**, pinned by the `one_point_eight_resolves_every_engine_block` test. What no rule covers at all (a modded engine id) still becomes stone.
15. **The item compat layer is not yet wired into the older codecs.** `protocol::compat` now has per-release item tables (`compat::items`) and behaviour-preserving stand-ins (`compat::behaviour`, task J4), and the modern codec shows an item its version lacks as a named stand-in rather than an empty slot. But only the modern codec decodes items at all: the 1.8.9–1.21.9 codecs still do not render stacks or run the gameplay path (item 10), so their item tables are foundational until task J5 routes them through gameplay. Two further temporary gaps inside this layer:
    - **Block items use a placeholder stand-in.** A *block* item a version lacks should follow its block's substitution rule (task J2); that block half is a sibling branch, so for now the generated tables map such an item to a generic item (`barrier`) and record it in `ITEM_FALLBACKS`. The connection is a TODO in `tools/gen/compat/gen_items.js` and is made when the two halves merge (regenerate the item tables after).
    - **The round trip is per slot, not per move.** `ItemTable::resolve_reported` keeps the server's real item when a client echoes back the stand-in in the *same* slot (which is what stops a creative client laundering a spear into a trident by re-sending that slot). When the client *moves* a stand-in into an empty slot the new slot has no real item to compare against; matching a report against the slot it was moved from is part of the older-codec work (J5). This cannot be exploited today because no older codec accepts creative-slot reports yet.

### B. Known Deviations Registry (Phase 1 — accepted on purpose)
These are **not bugs** in Phase 1 — they are documented, temporary compatibility gaps that must be recorded in the engine config and closed in Phase 2.

| Subsystem | Phase 1 deviation | Phase 2 target |
|-----------|-------------------|----------------|
| **Redstone** | Quasi-Connectivity (QC) ignored across inactive chunk borders | Full dependency graph with cross-chunk QC |
| **Fluids** | Scheduled-update flow with vanilla delays and levels on one queue, capped per tick; no entity push, no waterlogged flow | Deterministic fluid layers 1:1 with Vanilla |
| **Scheduled block ticks** | Falling blocks, crop growth and leaf decay on one scheduler plus a random-tick pass; pending ticks are written per chunk (`BT`/`BF` blobs, reloaded as the chunk loads) and **survive a restart**, but light is assumed full-bright and block tags are name lists | Real light and tag data |
| **Update order** | Simultaneous redstone updates ordered by the parallel graph | Strict deterministic directional-priority queue |
| **Entity spawn** | Batched async spawn every N ticks (every 40 ticks, per-player caps, sky/darkness test without light levels) | Per-tick precise spawner |
| **Mob AI** | Straight-line steering with step jumps and drop avoidance | Flow-Field navigation + cached A\* |
| **Lighting** | Real block/sky light by mask dilation, but recomputed per chunk send and per column only: no incremental relight on a block change, no cross-column propagation, no caching. The demo and the 1.8.9 codec still read `FullBright` | Incremental relight off journal events, cross-column propagation, caching |

### C. Engineering risks & trade-offs
- **RAM overhead: +15–25%.** SoA masks, Morton order, and redstone graphs cost more memory than classic structures. Accepted for cache-locality and SIMD wins.
- **x86-64 first.** The first version targets x86-64 with AVX2; other ISAs are deferred. Users on ARM/RISC-V are unsupported until later.
- **Determinism vs. parallelism.** Aggressive parallelism increases the risk of non-deterministic results if Safe-Point merges are wrong — needs strong test coverage.
- **Compatibility ceiling in Phase 1.** 70–75% Vanilla compliance means some contraptions (QC-dependent redstone, tick-perfect fluids) will behave differently until Phase 2.
- **External dependency choices.** Fjall was chosen over RocksDB for the KV store (it is what the engine uses); Elixir/OTP vs. C++/Rust for the Gateway is not finalized, and a wrong pick is expensive to reverse.

### D. How to report a problem
Open a GitHub issue with: the subsystem, whether it's a **bug** or an **accepted deviation** (check the table above first), reproduction steps, and — for performance issues — a Tracy capture or the relevant benchmark scenario. See [CONTRIBUTING.md](../CONTRIBUTING.md).
