# Веб-админка (нативный плагин `plugins/webadmin`)

> **Read this in other languages:** [English 🇬🇧](webadmin.md)
>
> Этапы **WEB1** (live-ops) и **WEB2** (карта + машина времени по журналу) из
> [`tasks/QUEUE-WEB-admin.md`](tasks/QUEUE-WEB-admin.md): один read-only HTTP-сервер внутри плагина.
> Связи — WEB3.

Веб-админка — это **нативный плагин** (уровень N): компилируется в `aether-server`, включается и
выключается как любой другой плагин и линкуется в процесс, поэтому читает живое состояние игры без
границы сериализации. Она ничего не пишет — на этих этапах из веба нет записи в мир. Один
HTTP-роутер отдаёт и страницы live-ops (дашборд, регионы, игроки/инвентари), и страницы
карты/машины времени; детали WEB2 — в README плагина (`plugins/webadmin/README.ru.md`).

## Архитектура

```
aether-server ── публикует в ──▶ реестр сервисов хоста ──▶ plugins/webadmin
   │  `ops@0.1` (ServerOps, трейт в crates/aether-ops)         │   один HTTP-роутер:
   │  TPS/MSPT · память · игроки · регионы · профили/инвентари │   live-ops + карта + время
   │                                                           │   простой HTML + немного JS
   ▼  ещё привязывает живой World (install_native) ───────────▶  карта + проигрывание журнала
 игровой тик ── сэмплит ──▶ crates/aether-server/src/web.rs
```

* `crates/aether-ops` — **единственный** общий крейт: трейт `OpsService` и его сериализуемые
  представления (`Dashboard`, `RegionStat`, `PlayerEntry`, `PlayerProfile`, `InventoryView`). Ядро
  реализует его, плагин читает. Ни один не знает внутренностей другого, и ядро собирается и
  работает без плагина.
* `crates/aether-server/src/web.rs` — серверная половина: метрики окна тиков, сэмплер регионов,
  хранилище профилей игроков и реализация `OpsService`. `plugins.rs` регистрирует его как
  `ops@0.1` **до** загрузки нативных плагинов, поэтому `requires = ["ops@0.1"]` плагина разрешается.
* `plugins/webadmin` — HTTP-сервер, токен-аутентификация и страницы. Без фреймворков и внешних CDN.

## Включение

Плагины выключены, когда `[plugins] dir` пуст. Задайте его и включите веб-админку:

```toml
[plugins]
dir = "plugins"                 # обнаружение плагинов должно быть включено (как для любого плагина)

[plugins.webadmin]
enabled = true
bind = "127.0.0.1:8090"         # по умолчанию; только loopback
token = "change-me"             # необязательно; без него используйте `/webadmin token`
```

Никаких секретов в коде нет. Если `token` не задан (или пуст), единственный вход — команда в игре
`/webadmin token` (уровень оператора 3), которая выдаёт **одноразовый** токен на пять минут и
печатает его; выдача нового отменяет старый. В браузер токен попадает как cookie `HttpOnly` после
формы входа либо напрямую как `?token=` (удобно для `curl`).

## Страницы

Плагин — единый HTTP-роутер и для WEB1 (live-ops), и для WEB2 (карта + машина времени).

| Путь | Что показывает |
|------|----------------|
| `/login` (GET/POST) | Форма входа по токену; верный токен ставит cookie и редиректит на `/`. |
| `/` | **Дашборд**: TPS, MSPT (средний и худший), игроки онлайн/макс, память, uptime, тики, отправленные колонки. Автообновление раз в 2 с из `/api/…`. |
| `/regions` | **Самые нагруженные регионы**: таблица с рейтингом и цветная тепловая сетка, одна ячейка на регион 32×32 чанка. |
| `/players` | Все известные игроки: состояние, адрес, первый/последний вход, время игры. |
| `/profile?id=<uuid\|имя>` | Профиль: первый/последний вход, время игры, замеченные адреса и живыми — позиция/здоровье/еда/режим. |
| `/inventory?id=<uuid\|имя>` | **Просмотр инвентаря**: живой онлайн или из сохранённого хранилища офлайн; основной инвентарь + хотбар + оффхенд, броня, выбранный слот. |
| `/api/dashboard`, `/api/regions`, `/api/players`, `/api/player?id=`, `/api/inventory?id=` | Те же данные в JSON. |
| `/map` | **Карта**: тайлы сверху вниз, панорама/зум, живой слой игроков/сущностей и ползунок времени по журналу (WEB2). |

### Карта и машина времени (WEB2)

| Путь | Что возвращает |
|------|----------------|
| `/map`, `/app.js` | Страница карты и её скрипт (панорама/зум, клик по блоку → история, ползунок времени, слой). |
| `/info`, `/head` | Размер тайла / зум / диапазон высот / голова последовательности. |
| `/tile?zoom&tx&tz` | Сырой RGBA-тайл живого мира. |
| `/tile_at?zoom&tx&tz&at=<seq>` | Тот же тайл, проигранный на прошлом номере события — «ползунок времени». |
| `/surface?x&z[&at]` | Верхний блок колонки. |
| `/history?x&y&z` | Все изменения одного блока, от старых. |
| `/changes?x&z&r[&since&until]` | Изменения блоков в радиусе за окно времени. |
| `/player?id=<uuid>[&since&until&x&z&r&limit]` | История поставил/сломал/взял/положил одного игрока. |
| `/overlay` | Метки игроков/сущностей. |

Всё только для чтения. Неизвестные маршруты → 404; не-`GET` запросы кроме `POST /login` → 405.
Браузер, запрашивающий страницу без токена, получает форму входа; запрос, который делает сам JS
страницы (`/api/…`, `/tile…`), получает обычный `401`.

## Метрики регионов — что сэмплируется, а что нет

Таблица регионов намеренно дешёвая: она сэмплирует **раз в секунду** на потоке тика и читает только
снимки, никогда не по блокам на горячем пути. Каждое поле:

| Колонка | Значение |
|---------|----------|
| `entities` | не-игровые сущности, стоящие в регионе на момент сэмпла |
| `block_entities` | загруженные контейнеры (сундуки, печи, воронки, варочные стойки) в регионе |
| `block_updates` | запланированные блочные/жидкостные тики, ещё висящие в регионе |
| `redstone_updates` | **всегда ноль**, пока редстоун-движок не подключён к серверу (сегодня это отдельный крейт) |
| `chunk_sends` | колонки, отправленные клиентам (стартовая выдача и стример), чей центр в регионе, с прошлого сэмпла |
| `cost` | `entities + 2·block_entities + block_updates + redstone + chunk_sends/4` — только для рейтинга |

Регионы, не затронутые в окне, затухают (стоимость делится пополам, удаляются при `samples == 0`),
поэтому тепловая карта — короткое скользящее среднее, а не суммарное за всё время. Числа — это
**сэмпл**, а не профайлер: всплеск между двумя сэмплами не приписывается. Это та «дешёвая,
сэмплируемая» метрика, которую просит бриф; внутриигровой профайлер — отдельная будущая задача.

## Замечания по безопасности

* По умолчанию слушает loopback; другой интерфейс оператор выбирает явно.
* Только чтение: в HTTP-слое нет маршрута, способного писать мир, а у трейта `ops` нет такого метода.
* Сравнение токена проверяет длину и накапливает байты, а не выходит на первом различии через `==`.
* Ответы несут `Cache-Control: no-store`; cookie — `HttpOnly; SameSite=Strict`. Токен, переданный
  как `?token=` при запросе страницы, превращается в этот cookie, чтобы JS-фетчи страницы тоже
  проходили аутентификацию.
* Секретов в git нет: `token` — конфиг оператора (в примере его нет), а одноразовый токен
  генерируется из `/dev/urandom` во время работы.

### Лимиты против DoS

Сокетный слой ограничивает возможности одного клиента, чтобы консоль нельзя было тривиально
завалить, даже если оператор открыл её наружу:

| лимит | по умолчанию | конфиг | что останавливает |
|-------|--------------|--------|-------------------|
| всего соединений | 32 | `max_conns` | флуд сокетами → потоки/память |
| на IP | 8 | `max_per_ip` | один адрес с безлимитными сокетами |
| пул потоков | ограниченный (≤16 воркеров, ограниченная очередь) | — | безлимитный рост потоков; сверх лимита — `503` |
| строка запроса | 8 КиБ | фиксировано | бесконечная строка запроса |
| заголовки (число / размер) | 64 / 16 КиБ | фиксировано | бесконечный поток заголовков |
| тело | 64 КиБ | фиксировано | слишком большая форма входа |
| дедлайн запроса | 10 с | `request_deadline_ms` | slowloris (байт за чтение); жертва получает `408` |
| рейт дорогих эндпоинтов | 50/с, всплеск 200 | `rate_per_sec`, `rate_burst` | долбёжка `/tile`, `/tile_at`, `/history`, `/changes`, `/player`; сверх — `429` |
| радиус / результаты / скан `/changes` | 256 блоков / 4096 строк / 100 тыс. событий | фиксировано | один запрос по безграничной области или журналу |

Тайлы `/tile_at` кэшируются по `(тайл, at)`, поэтому перетаскивание ползунка времени не
пересчитывает один и тот же переигранный тайл; живой рендер тайла делает снимок целой колонки под
одним локом, а не по блоку.

## Ограничения

* Поток на соединение, без keep-alive (сервер закрывает соединение после ответа). Нормально для
  операторской консоли на loopback; не рассчитано на публичный трафик.
* Хранилище профилей держит последние 16 адресов игрока.
* Представление эндер-сундука есть в форме (`InventoryView::ender`), но у движка пока нет
  эндер-сундука, поэтому оно пустое.
* Движок больше нигде не хранит время первого входа и время игры; хранилище веб-админки (`WB` +
  uuid в KV мира) — единственная запись, пишется при входе и выходе.

## Тесты

* `crates/aether-server/src/web.rs` — индексация регионов, работа с uuid, формирование инвентаря,
  окно тиков.
* `plugins/webadmin` — аутентификация (токен из конфига и одноразовый, разбор cookie, сравнение без
  раннего выхода), разбор HTTP (метод/путь/query/заголовки, percent-декодирование, кодирование
  ответа), маршрутизация и рендеринг страниц на мок-`OpsService`.
