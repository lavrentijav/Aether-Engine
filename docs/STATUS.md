### ✅ What exists today
The project has left pure design: **Phase 0 is implemented**, several Phase 1
subsystems have landed, and there is now a runnable demo plus `aether-server`,
which a vanilla client can join from 1.8.9 through 1.21.11 and 26.1–26.3 (the
modern versions run a server-side survival game).

| Leaf decay: a leaf recomputes `distance` to the nearest log one tick after a neighbour changes, and a non-persistent leaf at distance 7 drops its loot and disappears on a random tick | ✅ |
| Scheduled block ticks are durable: the pending falls, growth and flows are written per chunk (`BT`/`BF`, `game/tickstore.rs`) at autosave, every 30 s and on a clean stop, and reloaded as each chunk comes in — a restart no longer drops them | ✅ |
| Crop light is assumed full-bright (the engine does not simulate it), so crops grow in the dark; bone meal is not implemented | 🚧 Preview |
| Vanilla tags sent in configuration (block, item, fluid, entity type, game event — generated per release by `tools/gen/versions.py`): without the `minecraft:water` fluid tag a 1.21.11 client treats water as air (no swimming, no underwater view); `climbable` and `mineable/*` drive ladders and tool speed | ✅ |
| Journal checkpoints: a flush records, per column, which events its snapshots already hold, so loading a column replays only the events after that — not its whole history (1000 saved edits + 3 unsaved: 3 events read, was 1003) | ✅ |
| Snapshots stamped with the generator revision; one saved under an older generator is rebuilt as it loads (fresh terrain, the blocks players placed, then the journal) instead of bringing the old terrain back as a seam | ✅ |
| One client can no longer stall the server: a bounded outgoing queue and writer thread per connection, 30 s write timeout, clients silent for 30 s dropped, a repeat login replaces the old session, every departure logged with its reason | ✅ |
| Connection limits: `max_players` enforced at login (operators exempt), `max_connections` caps the connections served (`0` = `max_players*2 + 16`), `max_connections_per_ip` caps each address (`0` disables) | ✅ |
| Running as a service: clean stop on SIGINT/SIGTERM (players saved, world flushed), tick watchdog and status line, timestamped logs, `deploy/aether.service`, `AETHER_*` overrides, `tools/fetch-vanilla-data.sh`, operators bound to an address, whitelist | ✅ |
| Online mode and hybrid auth (`[auth]`): vanilla encryption handshake (server RSA-1024 keypair + AES/CFB8), Mojang `hasJoined` (uuid, name, skin properties), a durable premium-name lock store, the hybrid decision table (offline stays open to all; only names that completed online auth **here** are locked; an unlocked premium name is only *offered* auth — failure admits it offline, a mid-auth drop skips the offer for 5 min from the same address), and `/aether auth migrate <name>` | ✅ (unit-tested, not live-verified) |
| Item provenance from the survival layer (journal **format v4**): pickups, drops, chests, furnaces, crafting, eating, death drops and block drops are journalled, by diffing what a player can reach around each action. Topping up a stack is an `item_merge` (the units left a named source) rather than a move to the same slot that grew from nowhere; a `/give` mints the new units and then merges them; a split mints a new identity and moves the source; `item_derive` is reserved for a real output (craft/smelt/brew) from its consumed ingredients; a destroy carries a `reason` (consumed, despawn, crafted, creative replace, …); and `/audit` replays them with no anomalies in a full live session. v1–v3 history still decodes | ✅ |
| Bulk edit (CMD-30a/b): batched multi-block writes committed **atomically** as **one** journal revision (`EventBody::BlockGroup`, format v6; append-before-apply so a failed write never half-applies), pending reads that see the transaction's own writes, a bounded journal-backed undo (`BulkHistory`; spilled revisions still undo from the journal), and a serialised plan+apply (one coarse commit lock). Publication runs after the commit on a per-tick budget (`[bulk]`, `BulkPublisher`): shapes settle over the affected region using the placement pass to a reshape fixed point, each touched `16³` section is planned once and collapsed to one chunk-column re-send, and `after-block-break`/`after-block-place` fire **per changed block** (`after-block-place` is native-only; the frozen WASM ABI has no such export). A `BlockGroup` is treated as the block changes it carries by block history, worldgen-original, economy and the web history views; re-sending the column re-runs the **modern** codecs' light pass (1.17/1.18 send their pre-existing full-bright packet and 1.8 is FullBright; incremental cross-column relight is still S4). Publication is tick-budgeted (defaults 4,096 cells / 4 column sends / 8,192 hooks; the fixed-point settle, real-encoder re-send, fence-heavy sparse settle and sink-only hook steps are benched; the synchronous commit holds the cache write lock once, documented as an off-tick pause). The atomic commit itself is synchronous and documented as off-tick work (~0.8 s for 1M); the 1M test commits through the real journal+world path and then runs the budgeted publish | ✅ |
| Grouped revisions for operations other than bulk block edits, and packed, indexed history segments for the cold journal | 📋 |
| Parallel column generation + encoding on a server-wide pool of one worker per core; sections copied once per encode (cold 289-column join 20 s → 9.5 s on 4 cores, warm 1.8 s) | ✅ |
| Redstone / incremental relight / full staged physics | ❌ Not yet started |

It folds each tracked player's `block_set` events through their own actor index on a scheduler timer — never on the request path, so a command reads the cache — and tracks playtime itself in world ticks, checkpointed to KV on join/leave, so it survives a restart and a crash loses at most the last checkpoint. Distance/deaths/kills report `0` (the journal does not record them); a rename maps to the same UUID; `stats.stats.others` gates asking about someone else. It is the first WASM gameplay dependent; see [plugins/stats/README.md](../plugins/stats/README.md), [KNOWN_ISSUES §27](KNOWN_ISSUES.md).

A vanished player leaves the tab list, entity tracking, join/quit messages and mob targeting (vanished staff see each other); `/spectate` saves the exact state, switches to spectator (auto-vanish) and restores on `/spectate off`; the anti-xray override turns masking off/on or lowers its level for one admin and re-sends their columns; all four events are journalled — see [design/staff.md](design/staff.md), [Known Issues §23](KNOWN_ISSUES.md).
- ✅ **Region protection (CMD-29a/29b)**: `crates/aether-server/src/region.rs` adds the core spatial index behind region/claim protection — a per-chunk bucket (`ChunkPos → Arc<[RegionHandle]>`) built from an immutable snapshot and swapped atomically (`RegionStore`, mirroring the CMD-01/02 permission snapshots), with `RegionIndex::overlapping(pos)` yielding the covering regions in `(priority desc, id asc)` order, **no allocation and no lock on the hot path**; a region on a chunk border is entered into every chunk it touches. Query cost measured flat at ≈19 ns for 10 / 1k / 100k regions, and the full check (world filter, flag lookup, actor/membership test and the priority chain) at ≈42–45 ns regardless of region count (bench `region_index`). The check filters by `Region::world`, resolves explicit `build`/`use`/`pvp`/`explosion` flags through the priority chain (`Defer` moves to the next region, the action default is the final fallback), grants members/owners build/use when the flag is unset (plus per-player narrow action grants for claims trust), and skips everything for `aether.region.bypass` (an undeclared node, so an op by default and a non-op only by explicit grant); the denial line is configurable on the store. It is wired into block break/place, block and entity interaction, item use, player-vs-player attacks and explosion block damage — protected blocks are skipped while the rest of the blast still breaks. The model now lives in the dependency-free `aether-region` crate so both the server hooks and `plugins/regions` share the one index. **CMD-34a** ships the native regions plugin: `/rg`/`/region` `define`, `redefine`, `remove`, `priority`, `info` and `list` over cuboids, persisted as one JSON value in plugin KV, with an internal two-click wand (the native-only `before-block-dig` sets point 1 before the region check and a survival dig, and `before-block-interact` sets point 2, including the 1.8.9 tool right-click) while WorldEdit (CMD-36) is still pending. **CMD-34b** adds `/rg flag` over the typed core flag registry (boolean `build`/`pvp`/`use`/`explosion` are effective, `entry` is stored-only pending the teleport seam, plus text/integer and inert compatibility flags, `none` to clear), `/rg addmember`/`removemember` and `/rg addowner`/`removeowner` with persistence, and the per-world `worldguard.region.bypass.<world>` node (operators hold it by default); flags and membership survive a restart and a change reaches the check at the next snapshot. Claims remain CMD-35.
- ✅ **Claims (CMD-35a/35b)**: the native plugin `plugins/claims` adds GriefPrevention-style player claims on the CMD-29 region index — `/claim` (create a chunk claim or inspect), `/claim <radius>`, `/abandonclaim`, two-step `/abandonallclaims`, `/claimslist` (own claims, moderator cross-player view) and a golden shovel that claims on the second corner click (same corner/existing claim cancels). Claims persist as one JSON record per claim in plugin KV and are replayed into the core index at startup; overlapping another claim is refused while overlapping a WorldGuard region is allowed and decided by priority. Limits (`max-claims`, `max-claim-size`, `max-claim-blocks`/`max-accrued-blocks`, `max-radius`, `priority`) come from `[plugins.claims] config`; see [plugins/claims/README.md](../plugins/claims/README.md).
- ✅ **Vanilla world commands — `/setblock`, `/fill`, `/clone` (CMD-12a)**: the three commands run through the core bulk-edit transaction, so each one is atomic, one journal revision with the player as actor, and published through the normal column-resend/shape-settle path (`strict` skips the update/settle pass and resends the touched columns). `/setblock` supports `destroy` (loot and container contents dropped), `keep`, `replace` and `strict`; `/fill` supports `destroy`, `hollow`, `outline`, `keep`, `replace`, `strict`, the `replace <filter>` form and partial-property or tag filters; `/clone` supports `replace`/`masked`/`filtered`, `strict`, `force`/`move`/`normal` overlap rules (a self/overlapping `move` keeps the copied blocks) and the from-/to-dimension forms. Both bulk commands enforce vanilla's 32768-block cap before reading a cell, refuse positions outside the world, use 1.21.11 `en_us` success/failure lines, and ask the CMD-29 region check for **every cell they can touch** (including unchanged `destroy` targets and filtered boxes, with bypass honoured) before committing. Cave air and void air count as air for keep/masked. Op level 2 through `minecraft.command.{setblock,fill,clone}`. Block tags resolve through the configured data pack; with no pack the built-in fallback knows only the tags whose whole 1.21.11 membership is a fixed family rule (stairs/slabs/signs, the wood families excluding bamboo mosaic, flowers and a few other confirmed-exact sets) and refuses every other tag — including `#logs`, `#saplings`, `#sand`, `#dirt`, `#terracotta`, `#crops` and the coral tags — as an unknown tag rather than matching a guess. Known limitation: block-entity NBT in a block argument is refused (not silently dropped), `/clone` copies block states (not container contents), and a moved container's contents drop at the source while a replaced/destroyed one is cleared/spilled. See `crates/aether-server/src/commands/world_edit.rs`.

See [plugins/worldedit/README.md](../plugins/worldedit/README.md).

### ❌ What is cancelled / superseded
Decisions explicitly dropped or replaced during design. Kept here so the history is not lost.

| Cancelled / changed | Reason | Replaced by |
|---------------------|--------|-------------|
| **"100% Vanilla-accurate from day one"** (spec v1.0: *"priority is given to perfect Vanilla mechanics"*) | Blocked MVP on exotic edge-cases | **Progressive Enhancement** (v1.1): 70–75% in Phase 1, 95%+ in Phase 2 |
| **Per-tick precise entity spawner in Phase 1** | Too costly for the MVP tick budget | Batched async spawner in Phase 1; per-tick spawner deferred to Phase 2 |
| **Exact QC (Quasi-Connectivity) across chunk borders in Phase 1** | Requires the full cross-chunk dependency graph | Ignored in Phase 1 (registered deviation); implemented in Phase 2 |
| **OOP entity model** (`struct Player { ... }`) | Poor cache locality, blocks SIMD | Structure-of-Arrays (SoA) storage |
| **Fork of an existing Java server** (Paper/Purpur/Folia/Fabric) | Locks in Java internals; defeats the DOD/SIMD goal | Clean-room Rust engine |
| ❄️ **Non-x86 (ARM/NEON, RISC-V) targets** | Not cancelled — **deferred** until x86-64 AVX2 baseline is stable | Revisit post-Phase 1 |
