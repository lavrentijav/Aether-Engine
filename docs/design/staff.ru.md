# Staff — vanish, админ-спектейт и пер-админский контроль анти-иксрея (SP1)

> **Read this in other languages:** [English 🇬🇧](staff.md)

Статус: ✅ реализовано (2026-10-16), задача SP1. Политика — **нативный плагин**
(`plugins/staff`, уровень N по [`plugins.md`](plugins.md)); механизм — в ядре
(`crates/aether-server/src/staff.rs`, `src/visibility.rs`, `src/session.rs`),
потому что клиент *другого* игрока и путь рендера должны знать ответ без вызова
плагина. Известные пробелы — в [KNOWN_ISSUES §21](../KNOWN_ISSUES.ru.md).

## 1. Почему плагин и что остаётся ядру

Опциональная админская фича принадлежит плагину, а не ядру. Но vanish и
спектейт не самодостаточны: спавнит ли *другой* клиент скрытого игрока и
маскирует ли рендер руду, решает ядро на потоках, которые не могут ждать вызова
плагина. Отсюда разделение:

| слой | владеет |
|---|---|
| `plugins/staff` (нативный) | разбор команд, проверка прав, кто скрыт, какой уровень анти-иксрея, персистентность между входами, индикатор по тику, записи в журнал |
| ядро `staff.rs` | флаги на игрока, предикат видимости, снимок/восстановление спектейта, переопределение анти-иксрея |
| мост хоста (`HostBackend::staff_*`) | единственный API, через который плагин управляет механизмом |

Ядро нигде не ссылается на плагин; плагин отключаем как любой другой
(`[plugins.staff] enabled = false`), и без него ничего не скрывается.

## 2. Команды

Плагин сам регистрирует свои команды через реестр команд ядра
(`HostBackend::register_command`), поэтому они проходят тот же гейт прав, что и
команда ядра.

```text
/vanish [player]                              # aether.staff.vanish
/spectate [player]                            # aether.staff.spectate
/spectate off
/spectate xray off|engine|culling|<level>
```

`/spectate` намеренно больше не заглушка ядра: это админская фича этой задачи с
узлом `aether.staff.spectate`, а не ванильный `/spectate` со следованием за
сущностью. Пока не появится хранилище прав (CMD-01), гейт — флаг оператора,
та же заглушка, что у собственных команд ядра; узлы объявлены сейчас, чтобы
резолвер потом заработал без изменений.

## 3. Vanish

Скрытый игрок убирается из **таб-листа** и **трекинга сущностей** (деспавн, и
никогда не спавнится для зрителя, который его не видит), из **сообщений
входа/выхода** и из **нацеливания мобов**. Это пути, которые есть в движке, и
каждый спрашивает один предикат [`staff::visible_to`]:

```rust
!target.vanished || viewer.sees_vanished || (viewer.vanished && target.vanished)
```

Так скрытый стафф видит друг друга (заглушка для `aether.staff.vanish.see`,
выставляется операторам при входе), а скрытый зритель всё равно видит всех.
Скрытый игрок не спавнится для того, кто не должен его видеть, поэтому
рассылки движения по неотслеживаемой сущности клиент игнорирует.

Остальные пункты из брифа **не подключены, потому что в ядре нет самой фичи**, и
потому отсутствуют по построению, пока она не появится: `/list` всё ещё
заглушка CMD-09, дерево команд статично (нет динамического дополнения имён), нет
счётчика/списка игроков в server-list, кровати только задают точку спавна (нет
подсчёта спящих). Каждый из них обязан звать `staff::visible_to`, когда будет
построен — это единственное место, где живёт правило.

Открытие контейнеров в этом движке и так беззвучно (анимация и звук сундука
никому не рассылаются), поэтому контейнеры скрытого игрока беззвучны по
построению.

**Индикатор.** Каждый `tick_period` (1 с) плагин шлёт скрытому админу строку
action-bar. `ServerEvent::ActionBar` рендерится как System Chat с флагом overlay
на 1.19+; старые кодеки переписывают его в строку чата через
`ServerEvent::legacy`, поэтому индикатор виден во всех протоколах.

**Персистентность.** Плагин хранит *имена* скрытых в своём KV (`vanished`,
через перевод строки) и переприменяет vanish в `after-player-join`.
`[plugins.staff] persist = false` снимает vanish при выходе. При переподключении
есть окно в один тик (join-бёрст выполняется до колбэка входа плагина);
переприменение деспавнит игрока сразу после, поэтому утечка — не больше одного
тика собственного спавн-бёрста игрока.

## 4. Спектейт

`/spectate` сохраняет точное прежнее состояние — позицию/поворот, режим игры,
инвентарь, здоровье/голод/насыщение, опыт, эффекты, поглощение и был ли админ
уже скрыт — затем переключает в spectator (`GameMode::Spectator`, добавлен во
все кодеки) и авто-скрывает. `/spectate off` восстанавливает снимок и отправляет
его назад обычным путём `after_spawn` (позиция, режим, эффекты, здоровье, опыт,
весь инвентарь).

**Камера не прикрепляется**: в этом слое протокола нет пакета Set Camera, поэтому
`/spectate <player>` переносит спектатора на позицию цели, а не «в его глаза».
Это известный пробел, а не молчаливый.

## 5. Пер-админский контроль анти-иксрея

AX1 оставил анти-иксрей глобальным режимом плюс пер-игроцкий *bypass*. SP1
добавляет пер-игроцкое переопределение **уровня** на игроке и читает его первым
в `anti_xray_bypass`, `mask_for_render` и `mask_block`; игровой тик теперь делит
проходы по эффективному режиму каждого игрока:

| уровень | эффект |
|---|---|
| `off` | bypass — видно всё |
| `engine` | принудительно engine (только полностью погребённые руды) |
| `culling` | принудительно culling |
| `<n>` | culling с запасом `n` блоков (больше запас — меньше скрыто) |
| `default` | следовать `[anti_xray]` и правилам bypass |

Переопределение также *включает* анти-иксрей для оператора, который иначе его
обходит — в этом и смысл: спектящий админ может понизить уровень и увидеть
ровно то, что видит обычный игрок. При смене заново отправляются колонки,
которые держит админ (достижимое множество сначала инвалидируется, поэтому смена
запаса пересчитывается), а переопределение сбрасывается вместе со снимком
спектейта.

## 6. Журнал

Вход и выход из vanish и спектейта, авто-скрытие и каждое изменение уровня
иксрея добавляются в журнал мира как `EventBody::Custom` под тегом стаффа
(`TAG_CUSTOM_MIN`), полезная нагрузка `action\x1fdetail`, актор — UUID стаффа —
так ревизия может ответить «кто что и когда поменял».

## 7. Тесты

- `plugins/staff/tests/e2e.rs` гоняет плагин через настоящий `HostBackend` с
  записывающей заглушкой: проверка прав, персистентность через свежий плагин
  (перезапуск), авто-скрытие, гейт иксрея, журнал и индикатор.
- Юнит-тесты `aether-server` покрывают чистый предикат видимости и парсер
  уровня; переопределение видимости и восстановление проходят через тот же код,
  что тик и рендер.
