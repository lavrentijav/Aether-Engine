# Боковая панель (scoreboard sidebar) — нативный плагин `plugins/sidebar`

Статус: ✅ реализовано (2026-10-15), очередь SB1. Уровень **N** (нативный плагин) поверх API плагинов,
с небольшим ядровым механизмом снизу. Этот документ — запись «как сделано»; задача —
в [`QUEUE-SB-sidebar.md`](../tasks/QUEUE-SB-sidebar.md).

> **Читать на другом языке:** [English 🇬🇧](sidebar.md)

## Зачем

Каждому серверу нужна панель справа для каждого игрока: имя, ранг, монеты, пинг, онлайн, TPS,
убийства. Магазины, экономика и ранги хотят добавить туда строку. Это одна общая реализация без
мерцания, чтобы плагины не переизобретали пакеты scoreboard (и не путали детали каждой версии).

## Уровень: механизм в ядре, политика в плагине

Разделение следует правилу [`plugins.md`](plugins.md) — ядро держит механизмы, плагин держит
политику.

| | где | что |
|---|---|---|
| **ядро** (`crates/aether-server`) | `protocol/scoreboard.rs` + `PlayerHandle` | нейтральная модель панели, явные операции scoreboard, таблица `Wire` по версиям и per-player API (`update_sidebar`, `set_tab_header_footer`) с diff без мерцания |
| **плагин** (`plugins/sidebar`) | раскладки, условия и значения плейсхолдеров | какие строки видит игрок, собранные из `config.toml` и `%плейсхолдеров%`, с ограничением частоты |

Нативный плагин компилируется в сервер, поэтому его можно отключить как любой другой
(`[plugins.sidebar] enabled = false`), и ядро работает без него корректно. Плагин не собирает
пакеты; он передаёт ядру `SidebarBoard`, а ядро рисует его на диалекте каждого клиента.

## Ядро: per-player API пакетов

`SidebarBoard { title, lines }` (до пятнадцати строк, обычный текст с кодами `§`). Хост передаёт его
через методы `HostBackend`:

```rust
backend.set_sidebar(plugin, player, &board);        // показать / обновить
backend.clear_sidebar(plugin, player);              // скрыть
backend.set_tab_header_footer(plugin, player, &header, &footer);
```

`ServerBackend` отображает их на `PlayerHandle::update_sidebar` / `set_tab_header_footer`, которые
хранят последнюю панель и header/footer игрока и сравнивают с ними. **Пакет порождает только
изменённая строка.** Неизменившийся тик не пишет в сокет ничего — именно это не даёт периодически
пересчитываемой панели мерцать.

Diff выдаёт явные `ScoreboardOp` (`ObjectiveAdd`, `Display`, `TeamAdd`, `TeamUpdate`, `ScoreAdd`,
`ResetScore`, …). `Wire` (id пакетов + формы полей) превращает операцию в байты; `wire` выбирается
по `protocol_id()` кодека в `scoreboard::wire_for`, поэтому **добавление релиза — одна строка в одной
таблице**, а не правка каждого модуля кодека. `PlayerHandle::render` сам обрабатывает события
scoreboard и tab-list, поэтому двадцать четыре `encode` кодека не трогаются.

### Две стратегии отрисовки

- **До 1.20.2 (`SidebarStyle::Teams`)**: видимый текст живёт в prefix/suffix команды; запись счёта —
  невидимый цветовой код. Изменение строки перезаписывает prefix команды — один пакет, — так что
  objective, слот отображения и остальные строки никогда не разбираются и не собираются заново.
- **1.20.3+ (`SidebarStyle::DisplayNames`)**: текст живёт в display name счёта, а
  `number_format = blank` прячет красное число. Команды не нужны вовсе. Изменение строки — один
  пакет счёта.

Стратегия выводится из наличия number format (`Wire::number_format`).

### Покрытие версий

| протоколы | версии | текст | команды | слот | сброс |
|---|---|---|---|---|---|
| 47 | 1.8.9 | сырая строка `§` | формат 1.8, половины по 16 | byte | действие счёта `1` |
| 755–762 | 1.17–1.19.4 | компонент JSON | классический, половины по 64 | byte | действие счёта `1` |
| 763–764 | 1.20/1.20.1, 1.20.2 | компонент JSON | классический | byte / VarInt | действие счёта `1` |
| 765–772 | 1.20.3–1.21.8 | компонент NBT | строки NBT, классический порядок | VarInt | `reset_score` |
| 773–774 | 1.21.9–1.21.11 | компонент NBT | строки NBT + байт флагов | VarInt | `reset_score` |
| 775–777 | 26.1–26.3 | компонент NBT | как 1.21.11 | VarInt | `reset_score` |

Усечение: имена objective короткие; 1.8 разбивает длинную строку на prefix в 16 символов и suffix в
16 (разрез не оставляет висящий `§`); с 1.13 половины — по 64 символа. Заголовок — `aether.side`,
в стороне от ванильных имён `/scoreboard`.

Tab list: пакет `playerlist_header` (свой id в каждом поколении, `message_header` в 1.19.2), JSON до
1.20.3 и NBT с 1.20.3.

## Плагин: конфиг, раскладки, плейсхолдеры

`plugins/sidebar/config.toml` — только данные:

```toml
title = "&6&lAether"
update_hz = 4          # раз в секунду; по умолчанию 4, максимум 20
tab = false            # дублировать панель в header/footer списка игроков
clock = "world"        # что показывает %time%: "world" (по умолчанию) | "server"
mode = "override"      # "override" | "yield" (см. ограничения)

[[layout]]
priority = 0
lines = ["&7Online: &f%online%&7/&f%max%", "&7Ping: &f%ping%ms", "&e%player%"]

[[layout]]
priority = 10
permission = "sidebar.vip"
world = "minecraft:the_end"
lines = ["&dVIP", "&7Online: &f%online%"]
```

Рисуется раскладка с наибольшим приоритетом, чьи условия выполнены. Условия: `permission` (нужна
служба прав SDK; отказывает при отсутствии CMD-01/02), `world`, и `placeholder`/`equals`.

**Встроенные плейсхолдеры**: `%player%`, `%displayname%`, `%ping%`, `%online%`, `%max%`, `%world%`,
`%x%` `%y%` `%z%`, `%tps%`, `%health%`, `%level%`, `%time%` (мировые или серверные часы по настройке
`clock`), `%world_time%` и `%server_time%` (явные). `%ping%` и `%tps%` измеряются, а не выдумываются:
ядро замеряет round-trip keep-alive и сглаживает реальную частоту тиков. Коды цвета `&` переводятся
в `§`. Неизвестный токен остаётся буквально, чтобы опечатка была видна, а не исчезала.

**Другие плагины** регистрируют свои (`%economy_balance%`, `%rank_prefix%`) через службу
`sidebar@0.1`. Две формы, по одной на тир: нативный потребитель отдаёт замыкание, WASM-потребитель
импортирует `aether:sidebar@0.1` (свой пакет, версионируемый отдельно от замороженного мира;
добавление *импорта* никого не отклоняет), **объявляет** имя и **пушит** значение по игроку —
компонент не может отдать хосту замыкание, а у замороженного мира нет callback-экспорта:

```rust
// WASM-потребитель: объявить один раз, пушить значение по игроку.
sidebar::register_placeholder("economy_balance");
sidebar::set_placeholder("economy_balance", &p, balance.to_string());
sidebar::set_line(&p, 3, "&6Магазин: /shop");
```

Нативный потребитель резолвит службу один раз и отдаёт замыкание:

```rust
// нативный потребитель: получить службу один раз, затем
sidebar.set_line(player, 3, "&6%economy_balance%".into());
sidebar.register_placeholder("economy_balance".into(), Arc::new(|q| economy.balance(q.player)));
sidebar.toggle(player);   // /sidebar toggle
```

**Плагин** также регистрирует команду `/sidebar toggle|show|hide|reload` (через ядровый реестр
команд, поэтому она проверяется на права как любая другая).

## Тесты

- `crates/aether-server/src/protocol/scoreboard.rs`: diff (пусто при отсутствии изменений, один пакет
  на изменённую строку, добавление/удаление строк, переименование только заголовка, скрытие),
  ограничение в пятнадцать строк, разбиение 1.8, и кодирование на уровне пакетов по семействам —
  строковый критерий и действие счёта в 1.8, компоненты JSON, современные NBT + blank number format
  + `reset_score`, порядок полей команды 1.8 против современного, и tab list.
- `plugins/sidebar`: разбор конфига, разрешение плейсхолдеров + перевод цвета, и сквозной тест,
  который прогоняет настоящий `NativePlugin` через записывающий `HostBackend` (панель передана и
  разрешена, плейсхолдер + переопределение строки через службу, toggle, дублирование в tab).

Проверки по [`COMMON.md`](../tasks/COMMON.md): `cargo fmt`, `cargo clippy -- -D warnings`,
`cargo-locked test`.

## Ограничения

- **CMD-15 не сделан.** Ядро держит только то, что нужно панели (модель панели + эти пакеты).
  Полная ванильная модель `/scoreboard`, команды и хранилище — отдельная задача (CMD-15a/b);
  `mode = "yield"` разбирается, но бездействует, пока нет ванильной модели боковой панели, которой
  можно уступить.
- **`%level%` игрока равен 0.** Уровень опыта хранится в `PlayerState`, но ещё не проброшен в
  `PlayerExtra`; ping, мировое время и TPS настоящие.
- **WASM-плейсхолдеры пушатся, а не вызываются обратно.** WASM-провайдер обязан вызывать
  `set-placeholder` на каждом обновлении; обратного вызова хост→гость нет (у замороженного мира
  `aether:plugin@0.1.0` нет такого экспорта). Панель читает последнее отправленное значение при
  перерисовке.
- **Имена плейсхолдеров глобальны.** Два плагина с одним `%name%` делят слот (побеждает последнее
  значение, по каждому игроку); нативные замыкания важнее отправленных значений. Нормально для
  имён, различаемых по соглашению (`economy_balance`, `rank_prefix`), но не жёсткая гарантия.
- **id пакетов scoreboard для 26.1–26.3 взяты из собственного data-generator каждого релиза**, а не
  предположены: значения для 775/776 (сдвиг +2 от 1.21.11) и 777 (+4) — из `packets.json`, который
  выдаёт `net.minecraft.data.Main --reports` этого релиза (`set_display_objective`, `set_objective`,
  `set_player_team`, `set_score`, `reset_score`; пакет header/footer переименован в `tab_list`).
  Формы полей не изменились с 1.21.9+.
