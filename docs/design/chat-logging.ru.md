# Логирование чата, личных сообщений и команд (CH1)

Статус: ✅ реализовано (2026-10-16). Ядро, небольшой объём. Конфиг — `[chat]`; форматы строк и
события ниже стабильны. Формат журнала **v5** добавил тело «текст игрока».

## Что логируется

Каждая набранная игроком строка пишется дважды:

1. **В лог сервера**, с одним из трёх удобных для grep префиксов:
   - `[chat] <name> text` — обычное сообщение в чат.
   - `[pm] name -> target: text` — личное сообщение (`/msg`, `/tell`, `/w`).
   - `[cmd] name: /command line` — команда, вместе со слэшем.
2. **В мировой журнал**, как `EventBody::ChatMessage`: актор, время по настенным часам, где стоял
   говорящий, и текст. API истории (WEB/PA2) и веб-админка читают журнал, а не файл лога — потому
   и существуют оба.

Команда, отклонённая плагином (`before-chat`), и отклонённая строка чата всё равно попадают в
журнал как событие; в виде `[chat]` пишется только фактически доставленное сообщение. Команда
логируется до выполнения, поэтому в аудите остаётся попытка даже у отклонённой команды.

## Конфиг

```toml
[chat]
log = true           # публичный чат и личные сообщения
log_commands = true  # команды игроков
redact = ["login", "register", "l", "reg"]
```

Оба переключателя по умолчанию `true`. `redact` — список имён команд (без слэша, регистр не
важен), **аргументы** которых заменяются на `****` до записи и в лог, и в журнал; глагол
сохраняется, потому что аудит должен показать, что попытка входа была. Исходная строка
отбрасывается и не хранится. Команда, которой нет в списке, пишется как есть.

Сокрытие — по *имени команды*, а не поиск секретов в тексте: секрет, набранный аргументом
обычной команды (`/msg Bob мой пароль …`), всё равно будет залогирован, как и в консоли любого
сервера. Список по умолчанию покрывает типовые плагины аутентификации; при другом плагине
оператор добавляет его имена.

## Событие журнала

`FORMAT_VERSION` теперь **5**. Теги 7–9 — три вида текста игрока, по тегу на каждый, чтобы
колонка `kind` в зеркале истории различала их без чтения тела:

| тег | вид | peer | text |
|---|---|---|---|
| 7 | публичный чат | `ActorId::SERVER` | сообщение |
| 8 | личное сообщение | получатель | сообщение |
| 9 | команда | `ActorId::SERVER` | (скрытая) строка со слэшем |

Тело также несёт позицию говорящего, поэтому фильтр по радиусу (`/lookup radius:20`) находит
сказанное рядом. Событие чата не меняет мир: откат его игнорирует (`plan_rollback` работает
только с `BlockSet`), а реестр предметов сворачивает его как no-op. Старая история (v1–v4)
по-прежнему декодируется.

## Личные сообщения

`/msg <player> <message>` и алиасы `/tell` и `/w` — команды ядра (навсегда за ядром; плагин
может только встроиться в них). Отправитель видит `You whisper to <player>: <message>`,
получатель — `<sender> whispers to you: <message>`. Цель, не являющаяся игроком онлайн,
отклоняется; сообщение себе разрешено, как в vanilla. Полная группа `/msg` (селекторы,
компоненты в стиле `tellraw`) — это CMD-17a; здесь минимальная форма, нужная CH1 для логирования.

## Зеркало в PostgreSQL

В таблице `aether_events` появились `text TEXT` и `peer UUID` (добавляются через
`ADD COLUMN IF NOT EXISTS`, поэтому живое зеркало чинится при переподключении). `kind` — тег
выше; `aether_events_named` показывает расшифрованное имя вида. Всё остальное — предметы, блоки,
происхождение — идёт по прежним колонкам.

## Известные ограничения

- Чат живёт в общем мировом журнале, поэтому `/lookup` и `/inspect` могут вернуть события чата
  вместе с изменениями блоков. Они отображаются как `who said: …` / `who -> who: …` /
  `who ran: …`.
- Команды консоли и RCON пока не логируются здесь; CH1 ограничен строками, набранными игроками.
- Список `redact` по умолчанию — из брифа (`login`, `register`, `l`, `reg`), но `l` на этом
  сервере также алиас ядровой команды `/lookup`, поэтому запрос `/l player:…` логируется со
  скрытыми фильтрами. Оператору, использующему `/l` для истории, стоит убрать `l` из списка
  (пароли всё равно закрыты `login`/`register`/`reg`).
- Позиция — где говорящий стоял при обработке строки, а не точно в момент набора; с точностью до
  блока и в пределах тика.
