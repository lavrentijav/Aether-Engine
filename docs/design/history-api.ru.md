# History API (PA2)

Статус: ✅ реализовано (2026-10-15), стадия PA2 из [`QUEUE-WEB-admin.md`](../tasks/QUEUE-WEB-admin.md).

Журнал всегда хранил каждое изменение мира; PA2 — это **сторона чтения**, с
помощью которой инструмент оператора, плагин статистики или веб-админка задают
вопросы. Только чтение, постранично, за capability. Две половины: ядро
запросов в `aether-world::journal::history` и SDK-сервис `history`
(`aether:sdk/history@0.1`), открывающий его нативным и WASM-плагинам.

## Вопросы

| вопрос | ядро | сервис |
|---|---|---|
| кто менял блок `(x,y,z)` и когда — полная история блока | `Journal::block_history` | `block-history` |
| блок worldgen-original? | `Journal::is_worldgen_original` | `worldgen-original` |
| что было в этой области в это время? | `Journal::history_page` | `events` |
| откуда взялся этот предмет? | `Journal::item_chain` | `item-chain` |
| кто обращался к этому контейнеру? | `Journal::container_log` | `container-log` |
| чем занимался этот игрок? | `Journal::player_events` | `player-events` |

## Стоимость: по индексу на объект, никогда по всему журналу

Журнал и так пишет три индекса без полезной нагрузки рядом с событием: `E`
(событие), `X cx cz seq` (колонка), `P actor seq` (актор). PA2 добавляет
четвёртый, `I uid seq` (экземпляр предмета), поэтому вся история предмета —
это чтение по префиксу его собственных записей.

* Запрос по **блоку** или **контейнеру** идёт только по индексу `X` этой
  колонки назад и останавливается после `limit` попаданий в точную позицию.
  Колонка может быть занятой, но журналу хоть 100 млн событий — стоимость не
  меняется.
* Запрос по **игроку** идёт по его индексу `P`, а не по последним событиям
  всех.
* Запрос по **предмету** и цепочка происхождения идут по индексу `I`.
* Только полностью неограниченная выборка по времени/области откатывается к
  перебору номеров последовательности вниз от курсора, и прекращается, как
  только найдено `limit` совпадений: сначала новые, работа на страницу
  ограничена.

Страницы идут от новых к старым, курсор — это **номер последовательности**,
поэтому постраничность детерминирована независимо от часов, а добавление
между страницами видно как более новая страница, а не как переупорядочивание
старой. `limit` ограничен `MAX_PAGE` (1000), чтобы никто не запросил весь
журнал одним вызовом.

## Worldgen-original

`is_worldgen_original(x, y, z)` истинно, когда `last_change_at` не находит
события для позиции: генератор детерминирован, поэтому блок, который никто не
записал в журнал, — ровно то, что сделал сид. Блок, поставленный, сломанный и
возвращённый игроком, читается как **false** — журнал помнит касание, хотя
текущий блок выглядит естественным. Это проверка, нужная выживальческому
серверу перед оплатой блока, и то, что читают плагины `rewards`/`stats`
(PM2/CMD-47).

## Происхождение

`item_chain(root, depth)` проходит по индексу предметов назад через
`item_derive` (выход крафта/переплавки и потреблённые ингредиенты) и
`item_merge` (стак, добитый из другого) до `depth` поколений, без зацикливаний,
и возвращает события от старых к новым. `item_move` ничего не связывает: тот же
экземпляр на новом месте — не новый предмет.

## Capability

Сервис закрыт capability `history.read` вызывающего, применённой **один раз** в
провайдере SDK-плагина (`plugins/sdk`), читая эффективный грант из хоста.
Зависимый плагин просит capability в `plugin.toml`; оператор выдаёт её. Мост
хоста про capability не знает — так же, как для `permissions.admin`, — поэтому
нативный и WASM-зависимый проверяются одинаково.

## Кодирование на границе

Записи WIT `history` несут и компактные id (`from-block`/`to-block` id
состояний, `uid`, id `item`), и разрешённые имена, и строку места. Ядро
возвращает `aether_world::journal::Event`; сервер отображает их в записи для
плагинов (`crates/aether-server/src/plugins.rs`), разрешая имена через реестр
мира. Неизвестное имя вида события в окне выбирает **ничего**, а не молча
расширяет запрос.

## Ограничения

* Индекс предметов пишется с момента выхода фичи; в журнале, записанном более
  старой сборкой, нет записей `I` для уже лежащих на диске событий, поэтому
  `item_events`/`item_chain` видят историю предмета начиная с обновления. Мир
  можно и обнулить (storage-v2, поправка 2, без миграции), а индекс
  производный и при необходимости может быть перестроен отдельным проходом.
* У временного окна нет индекса времени: выборка берёт head и идёт по номерам
  последовательности вниз, останавливаясь на `limit` совпадений или на нижней
  границе времени окна. Запросы по объектам (блок/контейнер/игрок/предмет)
  используют свой индекс и так не делают.
* `history_page` с актором, но ещё и с фильтром области/времени, читает весь
  индекс этого актора на страницу. Для инструмента одного оператора нормально;
  горячий путь может позже добавить курсорный индекс.

## Тесты

* `crates/aether-world/src/journal/history.rs` — порядок и постраничность
  истории блока, worldgen-original, предикаты окна, индекс предметов, цепочка
  происхождения, лог контейнера.
* `crates/aether-plugin/src/sdk.rs` — мост передаёт id вызывающего и страницу,
  и отвечает нейтральным значением без провайдера.
* `plugins/sdk/src/lib.rs` — гейт `history.read` пропускает и отказывает.
* `crates/aether-server/src/plugins.rs` — разбиение uuid, отображение окна (в
  том числе неизвестный вид), рендер места.
* `crates/aether-plugin/tests/wit_world.rs` — мир сервисов SDK по-прежнему
  импортирует каждый интерфейс, включая `history`.
