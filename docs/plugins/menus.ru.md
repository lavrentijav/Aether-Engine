# Меню

> **Читать на другом языке:** [English 🇬🇧](menus.md)

Общий хост сундучных меню. Магазинам, китам, варпам, настройкам и модерации
нужны кликабельные инвентарные меню; вместо пятнадцати полусломанных одна
реализация — нативный плагин `plugins/menus` (тир **N**). Он **экспортирует**
сервис `aether:menus@0.1` — любой нативный или WASM-зависимый открывает меню
одним вызовом — и **загружает** декларативные файлы `menus/*.toml` для
случая, когда код вообще не нужен.

**Меню — это не инвентарь.** Окно меню придумано сервером: его слоты — заглушки
для действий, а не предметы. Ядро (см. `crates/aether-server/src/game/window.rs`)
перехватывает **любой** клик по меню — левый, правый, shift, обмен с номерным
слотом, offhand, выброс, перетаскивание, сбор двойным кликом, творческий
средний клик — передаёт его плагину, владеющему меню, и переселяет окно
заново. Ни один тип клика не может переместить предмет меню в реальный
инвентарь игрока или из него. Клик по уже закрытому меню (гонка или
переселение) игнорируется и никогда не применяется к окну, занявшему его
место.

## Открыть меню из плагина

Нативный зависимый достаёт сервис из реестра и вызывает:

```rust
use aether_plugin::menus::{MenuAction, MenuBuilder, MenuLayout, menus};

let Some(menus) = menus(ctx.services) else { return };
let def = MenuBuilder::new("shop")
    .title("&6Магазин")
    .layout(MenuLayout::Chest6)
    .button(0, "minecraft:emerald", "&aКупить меч",
            vec![MenuAction::Command("buy sword".into()),
                 MenuAction::Close])
    .filler("minecraft:gray_stained_glass_pane")
    .build();
menus.open(caller_id, &player, &def)?;
```

WASM-зависимый делает то же через импорт `menus` в мире `dependent`: один
вызов хоста, переадресованный нативному провайдеру в процессе. Интерфейс —
`aether:menus@0.1` (`crates/aether-plugin/wit-menus/`).

`open` заменяет текущее окно игрока; `update` заменяет один слот открытого
меню (или очищает его через `None`); `close` закрывает. Живое обновление
пересылает всё окно — меню небольшое, а частичное обновление — ещё одна вещь,
в которой клиент может разойтись с сервером.

## Декларативные меню

Файлы в `plugins/menus/menus/*.toml` (каталог настраивается
`[plugins.menus] menus_dir = "..."` в конфиге сервера) загружаются при старте и
по `/menus reload` (оп-уровень 2). Битый файл логируется и пропускается, но
никогда не фатален.

```toml
name = "shop"
title = "&6Магазин"
layout = "chest6"           # или rows = 6
permission = "shop.use"
open_commands = ["shop"]    # /shop открывает это меню с проверкой прав

[[item]]
slot = 0
material = "minecraft:emerald"
name = "&aКупить меч"
lore = ["&7Стоит &e100"]
glint = true
view_condition = "permission:shop.buy"
click_condition = "balance>=100"
actions = ["[economy] take 100", "[give] minecraft:diamond_sword 1", "[close]"]
```

* **Раскладки:** универсальные сундуки `chest1` … `chest6` (от 9 до 54
  слотов, 1–6 рядов по девять; `chest`/`chest3` — 27, `large_chest`/`chest6` —
  54), `dispenser` (9) и `hopper` (5). `rows = 1..=6` выбирает нужный размер.
* **Предмет:** `material`/`item`, `count`, `name`, `lore`, `glint`, `model`.
  `glint` (блеск чар) и `model` (id `custom_model_data`) пишутся по версии
  протокола (компонент на 1.20.5+, NBT до). Материал без `minecraft:`
  получает префикс; неизвестный предмет рисуется барьером, а не исчезает.
* **Условия** (необязательные `view_condition` и `click_condition`):
  * `permission:<node>` — у игрока есть узел (через `sdk.permissions`),
  * `group:<name>` — игрок в группе,
  * `balance>=<amount>` — баланс не меньше (сервис экономики),
  * `<placeholder> == <value>` и `<placeholder> >= <number>`.
* **Действия**, в порядке:
  * `[command] <cmd>` — выполнить от имени кликнувшего (с проверкой прав),
  * `[console] <cmd>` — выполнить от консоли,
  * `[message] <text>` — отправить игроку,
  * `[open] <menu>` — открыть другое меню по имени,
  * `[close]`, `[back]` — закрыть или вернуться к предыдущему меню,
  * `[sound] <name>`, `[economy] take <amount>`, `[give] <item> <count>`.

`/menu <name>` открывает любое меню по имени. `open_commands` каждого файла
регистрируются в реестре команд ядра, поэтому диспетчеризуются и проходят
проверку прав как любая команда — имя ядра отклоняется, а не затеняется.

## Плейсхолдеры

`%player%` разворачивается в имя кликнувшего везде, где используется строка
меню (заголовки, имена/lore предметов, сообщения, команды). Неизвестный
плейсхолдер остаётся как есть, а не стирается.

Плейсхолдеры от плагинов этот плагин **не** разворачивает: общий сервис
`placeholders` добавляется в SDK-плагин (очередь SB1), и именно он — единое
место для них. Пока он не появился, разворачивается только `%player%`;
точка расширения — `Menus::expand` в `plugins/menus`, который вызовет сервис
для каждого оставшегося `%name%`.

## Что на этом строится

* **Безопасность** — ядра, а не плагина: клик по меню выполняет только
  действия, написанные оператором, через механизмы хоста (реестр команд, чат,
  `[give]`), и никогда не трогает инвентарь напрямую.
* **Опциональные интеграции** (`economy`, `sound`, `players`) достаются как
  сервисы и деградируют честно: условия `balance` закрыты по умолчанию, а
  `[economy]`/`[sound]` инертны, пока этих сервисов нет.

Текущие ограничения (формы окна, рендер glint/model, кодеки до 1.20.2) — в
[KNOWN_ISSUES §20](../KNOWN_ISSUES.ru.md).
