# Aether-Engine

> **На других языках:** [English 🇬🇧](README.md)

**Высокопроизводительный игровой сервер Minecraft нового поколения, написанный с нуля на Rust.**

Кодовое имя проекта: **Aether** · Версия спецификации: **1.1 (Production Candidate)** · Статус: **pre-alpha / стадия проектирования**

---

## Что такое Aether?

Aether Engine — это игровой серверный движок для Minecraft, написанный «с чистого листа» на Rust. Это **не** форк и **не** патч Java-серверов (Paper, Purpur, Folia, Fabric). Вместо этого движок переосмысливает внутреннее устройство сервера под современное железо:

- **Data-Oriented Design (DOD)** и хранение по принципу Structure-of-Arrays (SoA).
- **SIMD-first** математика (Scalar → SSE4.2 → AVX2 → AVX-512, выбор в рантайме).
- **Cache-locality first** — раскладка памяти с индексацией Morton (Z-order).
- **Lock-free / work-stealing** параллелизм вместо глобальных блокировок.

Цель: обслуживать **1000+ игроков в одном игровом пространстве** при стабильном **20 TPS (50 мс/тик)**, с параллельной обработкой физики, редстоуна, света и AI.

## Ключевые цели проекта

| Цель | Подход |
|------|--------|
| Максимальное использование CPU | Векторизованные (SIMD) подсистемы + work-stealing планировщик |
| Изоляция сети и логики | Безсостоянийный **Network Gateway** ⇄ изолированные процессы **World Engine** на каждый мир |
| Наблюдаемость в реальном времени | Встроенная телеметрия Tracy + Prometheus по под-тикам |
| Безопасная расширяемость | Двухуровневые плагины: **Native C-ABI** (быстро) + **WebAssembly** (песочница) |
| Поддержка старых миров | CLI `Aether-Convert`: Anvil `.mca` → KV-хранилище |
| Предсказуемая совместимость | **Progressive Enhancement** (70–75% Vanilla в Фазе 1 → 95%+ в Фазе 2) |

## Архитектура в двух словах

```
            [ Клиентский трафик (Internet) ]
                        │
                        ▼
            ┌──────────────────────┐
            │   Network Gateway    │   Без состояния: TLS, защита от DDoS,
            │   (Elixir/OTP / C++) │   санитизация пакетов, маршрутизация
            └───────────┬──────────┘
                        │  Internal Binary Protocol
        ┌───────────────┼───────────────┐
        ▼               ▼               ▼
 ┌────────────┐  ┌────────────┐  ┌────────────┐
 │ World #1   │  │ World #2   │  │ World #N   │   Каждый мир = изолированный
 │ (Rust)     │  │ (Rust)     │  │ (Rust)     │   процесс ОС. Падение одного
 └────────────┘  └────────────┘  └────────────┘   мира не затрагивает другие
                                                   миры и сам Gateway.
```

### Иерархия памяти

```
World → Region → Chunk (16×16) → Sub-Chunk (16×16×16) → AVX-Cell (4×4×2)
```

**AVX-Cell** (32 блока × `u16` = **64 байта**) — атомарная единица памяти, ровно одна строка кеша CPU. Считывается за **1** операцию AVX-512, **2** операции AVX2 или **4** операции SSE. Данные Sub-Chunk разделяются на SoA-маски (`SolidMask`, `LightOpacity`, `Collision`, `RedstoneFlags`, `BlockStateID`), чтобы каждая подсистема читала только нужные ей байты.

## Основные подсистемы

- **Физика** — поэтапный конвейер (`Input → Movement → Collision → Environment → Velocity → Finalize`) с SIMD broad-phase и O(1) быстрым путём через кэш окружения.
- **Редстоун** — компилируемый **Directed Dependency Graph (DDG)**: ноль пространственных запросов, пока ничего не меняется.
- **Освещение** — асинхронный flood-fill по ячейкам со слиянием в safe-points.
- **Сущности / AI** — ECS-хранилище + Flow-Field навигация (O(1) для толп) и кэшируемый A\* для одиночек.
- **Хранилище** — KV-база (RocksDB / Fjall), блобы Sub-Chunk со сжатием Zstandard.
- **Телеметрия** — зоны Tracy на каждую фазу тика + экспортёр Prometheus + внутриигровая команда `/aether profile`.

### Запуск демо — *«уже работает?»*

Клиента для игрока пока нет, но можно посмотреть, как движок реально работает.
Бинарник `aether` генерирует мир, рисует его срез, сбрасывает игрока с высоты и
тикает физику до приземления, сохраняет затронутые чанки и печатает телеметрию:

```bash
cargo run -p aether-demo            # использует ./aether.toml (создаётся при первом запуске)
cargo run -p aether-demo -- my.toml # свой файл конфигурации
```

Настройки в [`aether.toml`](aether.toml): генератор (`noise`/`flat`), бэкенд
хранилища (`memory` или `fjall` для записи на диск в `storage_path`), сид,
точка спавна, число тиков и размер среза. Для записи мира на диск поставьте
`storage = "fjall"` и запустите release-сборку:

```bash
cargo run -p aether-demo --release
```

### Подключиться клиентом Minecraft — *«уже можно зайти?»*

Есть экспериментальный сервер, к которому **можно подключиться ванильным
клиентом**. Он намеренно минимальный — только **Minecraft 1.8.9 (протокол 47)**,
offline-режим, без сжатия/шифрования — и спавнит вас в **плоском мире с
максимальным светом (full-bright), в креативе**, отдаваемом движком.

```bash
cargo run -p aether-server            # слушает 127.0.0.1:25565 (см. aether-server.toml)
```

Затем в клиенте **Minecraft 1.8.9**: *Сетевая игра → Прямое подключение →*
`127.0.0.1`. В списке серверов виден MOTD; при входе вы стоите на плоском мире.

> ⚠️ **Не выставляйте это в интернет.** Сервер работает в **offline-режиме без
> аутентификации, шифрования и сжатия** — любой, кто дотянется до порта, может
> зайти под любым именем. Поэтому по умолчанию он слушает только loopback
> (`127.0.0.1`). Меняйте `host` на `0.0.0.0` лишь в доверенной локальной сети.
>
> Область применимости: это превью Фазы 3, а не совместимый сервер — только
> 1.8.9, из геймплея лишь спавн и осмотр, свет — фолбэк `FullBright` (всегда
> максимум). Более новые версии клиента отклоняются на хендшейке.
