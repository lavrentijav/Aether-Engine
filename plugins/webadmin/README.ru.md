# Веб-админка — live-ops, карта и машина времени (WEB1 + WEB2)

Read-only веб-интерфейс администратора, оформлен как **нативный плагин** (`plugins/webadmin`,
уровень N). Один встроенный HTTP-сервер (без фреймворков, без CDN) отдаёт оба этапа брифа.

- Задача очереди: **WEB1** + **WEB2** — `docs/tasks/QUEUE-WEB-admin.md`.
- Сервер привязывает живой `aether_api::World` в `install_native` и публикует сервис live-ops
  (`ops@0.1`, `crates/aether-ops`), который плагин резолвит для счётчиков. См. `docs/webadmin.ru.md`
  и `KNOWN_ISSUES §A20`.
- Вход — статический `[plugins.webadmin] token` или пятиминутный одноразовый `/webadmin token`,
  переносится cookie `HttpOnly` или `?token=` (или `X-Token`).

## Что делает

| часть | что |
|---|---|
| **Дашборд** | TPS/MSPT (средний и худший), игроки, память, uptime, отправленные колонки — главная live-ops. |
| **Регионы** | Самые нагруженные регионы: сэмплируемый рейтинг стоимости тика плюс тепловая сетка. |
| **Игроки** | Все известные игроки, с живыми/сохранёнными **инвентарями** и профилем (замеченные IP, первый/последний вход, время игры). |
| **Карта** | Тайлы сверху вниз: самый верхний непустой блок каждой колонки, с цветом и затенением по высоте. Тайлы кэшируются по `(zoom, tx, tz)` и **перерисовываются на изменении** — правка блока сбрасывает все тайлы, накрывающие колонку. Зум — `2^zoom` блоков на пиксель. Игроки/сущности — отдельный слой. |
| **Ползунок времени** | Перематывает журнал: `/tile_at?…&at=<seq>` рисует мир **каким он был** в любом прошлом номере события, проигрывая журнал поверх базовой генерации. `/history?x=&y=&z=` — полная история блока; `/changes?x=&z=&r=` — изменения области за окно времени. |
| **История игрока** | `/player?id=<uuid>` возвращает всё, что игрок поставил, сломал, взял или положил, с фильтром по времени и области; каждая строка несёт координаты для перехода на карте. |

Всё **только для чтения**. Ни один маршрут, функция или хук в этом крейте не пишет блок, предмет
или файл. Машина времени вычисляет прошлые состояния; она их не восстанавливает.

## Маршруты

Обычный HTTP/1.1, один JSON на запрос. Опциональный общий `?token=` (или `X-Token`).

| маршрут | что возвращает |
|---|---|
| `GET/POST /login` | форма входа; верный токен ставит cookie и редиректит на `/` |
| `GET /` | **дашборд** (WEB1) |
| `GET /regions` | таблица самых нагруженных регионов и тепловая сетка |
| `GET /players` | список игроков |
| `GET /profile?id=<uuid\|имя>` | профиль одного игрока |
| `GET /inventory?id=<uuid\|имя>` | инвентарь одного игрока (живой или сохранённый) |
| `GET /map` | страница **карты** (встроенные HTML + JS, без CDN) |
| `GET /app.js` | скрипт страницы карты |
| `GET /api/dashboard`, `/api/regions`, `/api/players`, `/api/player?id=`, `/api/inventory?id=` | те же данные в JSON |
| `GET /info` | `{tile_px, max_zoom, y_min, y_max, head}` |
| `GET /head` | `{head}` — номер события «сейчас» |
| `GET /tile?zoom&tx&tz` | сырой RGBA-тайл (блоб; заголовок `X-Tile-Px`) |
| `GET /tile_at?zoom&tx&tz&at` | тот же тайл, проигранный на событии `at` |
| `GET /surface?x&z[&at]` | `{x,z,y,id,name,water}` — верхний блок колонки |
| `GET /history?x&y&z` | все изменения одного блока, от старых |
| `GET /changes?x&z&r[&since&until]` | изменения блоков в радиусе за окно времени |
| `GET /player?id=<uuid>[&since&until&x&z&r&limit]` | действия одного игрока |
| `GET /overlay` | метки игроков/сущностей (пусто, пока WEB1 их не даёт) |

## Модули

| модуль | роль |
|---|---|
| `color` | имя блока → RGB (палитра офлайн-примера `vanilla_map`) со стабильным фолбэком |
| `source` | `MapSource` / `HistorySource` — два read-only представления мира, с impl для `aether_api::World` |
| `map` | рендер тайлов, кэш, инвалидация |
| `timemachine` | проигрывание журнала: история блока, изменения области, тайлы «как было» |
| `playerhist` | запросы по игроку и человекочитаемые сводки |
| `auth` | токен-аутентификация: токен из конфига, одноразовый, разбор cookie |
| `pages` | HTML-страницы live-ops (дашборд, регионы, игроки, профиль, инвентарь) |
| `http` | встроенный сервер, роутер и страница карты |

Чистые модули не зависят от хоста плагинов, поэтому тестируются на моке и обычном `World`; обёртка
плагина (`WebAdminPlugin`) тонкая и владеет только жизненным циклом сервера.

## Подключение

Сервер собирает плагин с живым миром и добавляет его в `install_native`
(`crates/aether-server/src/plugins.rs`):

```rust
let plugin = WebAdminPlugin::with_world(world);   // Arc<aether_api::World>
host.add_native(&file, &caps, &config, Box::new(plugin))?;
```

В `init` плагин резолвит `ops@0.1` из реестра сервисов хоста (манифест его `requires`), строит
`WebAdmin` из привязанных представлений мира и запускает сервер. `WebAdmin::handle(&Request)` —
чистый роутер, который тесты гоняют без сокета.

## Конфиг

`WebAdminConfig`: `tile_px` (по умолчанию 128), `y_min`/`y_max` (по умолчанию −64…319),
опциональный `token` и `history_limit`. Плагин читает `bind` и `token` из своей секции
`[plugins.webadmin]`; токен попадает в общий `Auth`, а `/webadmin token` выдаёт одноразовый.

## Тесты

`cargo-locked test -p aether-webadmin-plugin` — 40 юнит-тестов (палитра, рендер/инвалидация
тайлов, зум, проигрывание, история, вход/login, маршруты и страницы live-ops, живой TCP-запрос) плюс
4 end-to-end теста на настоящем `World` (карта/машина времени и live-ops маршруты через тот же
роутер).
